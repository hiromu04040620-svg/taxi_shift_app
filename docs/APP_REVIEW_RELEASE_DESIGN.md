# App Review Release Design

## 目的

TaxiShift 1.0 を、日常的に使いやすい画面へ整えたうえで、非消耗型アプリ内課金
`remove_ads` を審査員が見つけ、読み込み、購入、復元できる状態にして App Review へ
提出する。

## 採用方針

既存のドメインモデル、ローカルデータ、2タブ構成は維持する。初回審査中のため、
全面的な情報設計変更や外部広告 SDK の追加は行わない。

- カレンダー、日別入力、サマリー、設定を Material 3 の静かな業務画面として整理する。
- iPhone と iPad で余白、情報密度、固定要素が破綻しないレスポンシブ構成にする。
- 広告枠と設定の両方から、専用の「広告非表示」画面へ移動できるようにする。
- `remove_ads` は買い切りであること、価格、購入状態、復元、再読み込みを明示する。
- 外部広告 SDK や追跡は 1.0 では導入せず、購入前はアプリ内の案内枠を表示する。

## 課金アーキテクチャ

購入ストリームの購読を設定画面の Widget からアプリ全体の Riverpod Controller へ移す。
Controller はアプリ起動中ずっと次を担当する。

1. App Store の利用可否を確認する。
2. 製品 ID `remove_ads` の商品情報を取得する。
3. 購入、保留、キャンセル、エラー、復元を一つの状態モデルで管理する。
4. 購入または復元に成功したらローカルの Premium 状態を更新する。
5. 配信完了後に `completePurchase` を実行する。
6. 画面を離れても購入更新を取りこぼさない。

プラグイン呼び出しは Gateway で隔離し、商品取得、購入、復元、完了処理を Widget
テストから差し替えられるようにする。

## 審査で確認できる購入導線

- カレンダーとサマリー下部の案内枠を押すと専用購入画面を開く。
- 設定の先頭付近にも「広告非表示」を置く。
- 専用画面では商品情報取得中、購入可能、処理中、購入済み、取得失敗を区別する。
- 取得失敗時も購入ボタンを無効化するだけで終わらせず、理由と再読み込み操作を示す。
- 「購入を復元」は常に見つけられる位置に置く。

## Fastlane / App Store Connect API

Fastlane に以下の段階を持たせる。

- `asc_status`: バージョン、ビルド、IAP、ローカリゼーション、添付動画を監査する。
- `release_candidate`: テスト後に IPA を作成し、App Store Connect へアップロードする。
- `sync_review_assets`: メタデータ、スクリーンショット、審査メモを同期する。
- `submit_review`: 有効なビルド、提出可能な IAP、審査動画が揃った場合だけ提出する。
- `release_status`: 提出後の審査状態を再取得する。

API で変更できない却下済み IAP の編集と、物理端末での Sandbox 購入だけは手動確認と
する。秘密鍵は環境変数または Git 管理外の `.p8` から読み込む。

## 検証と提出条件

- `dart format --output=none --set-exit-if-changed .`
- `flutter analyze`
- 全 Flutter テスト
- iPhone と iPad サイズの Widget / スクリーンショット確認
- 実機で商品価格が表示され、Sandbox 購入と復元が成功すること
- 実機動画がホーム画面から始まり、主要機能と購入成功を含むこと
- App Store Connect 上で IAP が提出可能、ビルドが有効、動画が添付済みであること

上記を満たすまでは Fastlane が審査提出を停止する。
